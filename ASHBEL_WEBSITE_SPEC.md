# ASHBEL WEBSITE SPEC

## 1. Purpose

Build a premium Hebrew RTL public website for Ashbel Aluminum.

The website is not a generic aluminum catalog and not an internal CRM. It is a high trust marketing and lead intake website for quality aluminum projects.

Primary business goal:
Convert visitors into high quality leads by encouraging them to send plans, photos or project details for initial professional direction.

Secondary goals:
- Present Ashbel Aluminum as a serious professional execution company.
- Support private home owners, villa projects, architects, contractors and developers.
- Explain services, styles, product categories and relevant Klil system families in clear language.
- Prepare future connection to AshbelOS lead intake.

## 2. Positioning

Ashbel Aluminum should be positioned as:

A professional aluminum execution company for private homes, villas and quality projects, with an emphasis on accurate measurement, clean installation, coordination with plans and responsibility from first review to final installation.

Avoid positioning as:
- Cheap aluminum contractor.
- Generic handyman service.
- Pure product catalog.
- Overly technical manufacturer.
- Fake tech platform.

## 3. Target audiences

1. Private home owners building a new house.
2. Families renovating an existing home.
3. Villa owners.
4. Architects and interior designers.
5. Contractors.
6. Developers and project managers.
7. Clients who want to replace old windows or upgrade openings.

## 11. Products and Klil Series page

Purpose:
Add professional credibility by explaining relevant aluminum systems and Klil series families in simple useful language.

Important legal and content rules:

- Do not copy Klil text.
- Do not copy Klil images.
- Do not claim official authorized installer status unless proven.
- Do not present technical specs that Ashbel cannot stand behind.
- Use plain explanatory language.
- Mention Klil only where true and commercially relevant.

Required product sections:

1. פרופיל בלגי
2. חלונות הזזה
3. ויטרינות ודלתות הזזה
4. תריסים והצללה
5. רשתות
6. מפתחים גדולים
7. פרגולות אלומיניום, if promoted

Suggested Klil series content structure:

- Series name
- Short explanation
- Suitable use
- Main benefit in plain language
- What to check before choosing

Example style:

### קליל בלגי 1700
מערכת בסגנון בלגי המיועדת לפתחים שבהם רוצים מראה עדין, חלוקות פנימיות ותחושה כפרית או קלאסית. מתאימה בעיקר לחלונות ופתחים שבהם העיצוב חשוב לא פחות מהתפקוד. לפני בחירה בסדרה חשוב לבדוק את גודל הפתח, סוג הפתיחה, עובי הזכוכית הדרוש ורמת האיטום הנדרשת בפרויקט.

Do not overload the public page with dense engineering data.

7. מבצעים התקנה.
8. מבצעים בדיקת גמר ומסירה.

## 14. Professionals page

Public label:
אזור מקצוענים

Purpose:
Impressive and useful intake path for architects, contractors, developers and serious private clients.

Phase one is not real login and not client dashboard.

Required copy direction:

אזור מקצוענים לאדריכלים, קבלנים ויזמים.
שלחו תוכניות, מפרטים או תמונות מהשטח, ונבחן את הפרויקט לצורך הכוונה מקצועית ראשונית, בחירת מערכות אלומיניום מתאימות ותיאום המשך עבודה.

Required options:

- Upload plans or files, if technically implemented.
- Request technical consultation.
- Request proposal review.
- Request measurement coordination.
- Send project details via form.
- WhatsApp alternative.

Do not write:
- התחברות למערכת
- קבלת הצעת מחיר מיידית
- דשבורד אישי
- תמחור אוטומטי

Unless those features are actually built later.

## 21. First build acceptance criteria

The first implementation is acceptable only if:

- All required pages exist.
- Hebrew RTL works across pages.
- Mobile layout is clean.
- No lorem ipsum.
- SEO metadata exists for every page.
- Header and footer are complete.
- Sticky mobile CTAs work.
- Professional portal is implemented as intake flow, not fake login.
- Build passes.
- Lint passes or all lint issues are documented.
- No broken internal links.
- Placeholder images are clearly marked for replacement.

## 22. Future AshbelOS connection

Future integration path:

Website lead form -> AshbelOS lead intake API -> lead classification -> proposal readiness -> next action -> activity log.

Do not implement this integration in the first website build unless endpoint details and auth are explicitly provided.
